Architecture:

Movement Action Client — sends (x,y,z) goals, gets feedback/results.

A Motion Coordinator Node* — ROS2 Action Server for A* planning, GPS ↔ grid conversion, waypoint generation.

Drone Control Node — receives waypoints, sends to MAVROS.

This project shows them how to navigate a drone using the A* path planning algorithm integrated into ROS 2based
system. It consists of three coordinated ROS nodes each responsible for a specific task. So we have movement action client node, motion coordinator node, and drone control node.

** Movement Action Client Node
We start by initializing the node and creating an action client instance for our custom movement action. This client will send movement goals in X Y and Z directions to the server. In the next part, when a
request is sent using send movement request, we first check if the server is available. If it is, we send a goal message
and attach response.

In the goal response call back, we simply verify if the goal was accepted. If yes, we proceed to fetch the result. The
get result call back handles the final confirmation whether the movements were sent successfully or not based on the
result status from the server. Lastly, feedback callback is triggered during the process continuously updating the
client with X, Y, and Z uh progress values. The node named the waypoint push node is responsible for converting movement
requests into a selfgps waypoints applying path planning and pushing them to the third node. We start by initializing
the node and creating a client for the get waypoint service which is used to send the final waypoint list to the third
node. We also define an action server that listens for movement goals in X Y Z coordinates and once it receives a goal
execute call back is triggered. Inside the callback uh the node logs and publishes the goal as feedback. Then we set up
the grid with define obstacles.

But before that we convert obstacles GPS coordinates to grid coordinates. Also both a start and the goal points are
converted into grid coordinates. After setting up the A* star path planning algorithm is applied to find a safe path
avoiding obstacles. If successful that path is converted back to GPS waypoints. Finally waypoints will be packed into
get waypoints request and sent to the third node.

Let's now look at the final piece of the system which plays a crucial role in translating and pushing waypoints to the
drone using MAVROS. This node listens for waypoints generated by the A* star planner and prepares them in the required
MAVROS format. It uses MAVROS waypoint Push service to send those waypoints to the drone. Each waypoint includes a
defined command along with associated  parameters like velocity, altitude and geographic coordinate. Once all waypoints
are configured, the node transmits the entire set to the drone. Before moving to simulation part, I would like to
explain shortly about MAVROS waypoint message. Waypoint message is a custom ROS message that defines a single waypoint
used in autonomous drone missions. This message allow us to define precise navigation points including location actions
and flight behavior. Let me walk you through the structure of MAVROS waypoint message. This uh message includes a
frame. This tells the drone how to interpret the coordinates. For example, 1  means global GPS and 0 means a local
coordinate which is relative to the drone's starting position. Command for this 16 means fly to a point, 22 is take off
and 21 is for landing. The next one is current. set this flag let's say or parameter to true only for the first
waypoint. This tells the drone where to start. The next one is auto continue. Uh this uh determines whether the drone
should automatically go to the next wayoint after completing the current one. Uh parameter one to parameter four. These
parameters depend on the command. They can define things like loiter time, radius or your orientation. Finally, we have
the coordinates. We have the latitude in degrees, then longitude in degrees and the altitude in meters. Together, this
uh this message finally defines a waypoint, its position and behavior. All right, that wraps up the software
architecture of our autonomous drone system.
